## 🔐 Защита данных базы данных

```
┌─────────────────────────────────────────────────────────────────────┐
│                    ЧТО ПРОИСХОДИТ С ДАННЫМИ БД                      │
└─────────────────────────────────────────────────────────────────────┘

При деплое:

1. docker-compose down
   ├─ Останавливает контейнеры ✅
   ├─ Удаляет контейнеры ✅
   └─ Сохраняет volumes ✅ ← ДАННЫЕ В БЕЗОПАСНОСТИ!

2. docker-compose build
   └─ Создает новые образы (код обновляется) ✅

3. docker-compose up -d
   ├─ Создает новые контейнеры ✅
   ├─ Подключает те же volumes ✅
   └─ База данных с теми же данными! ✅

┌───────────────────────────────────────┐
│  ДАННЫЕ БД УДАЛЯТСЯ ТОЛЬКО ЕСЛИ:      │
├───────────────────────────────────────┤
│  ❌ docker-compose down -v            │
│     (с флагом -v!)                    │
│                                       │
│  ❌ docker volume rm postgres-data    │
│     (явное удаление volume)           │
│                                       │
│  В deploy.sh эти команды НЕ           │
│  используются!                        │
└───────────────────────────────────────┘
```


## 🔄 Временная шкала деплоя

```
┌─────────────────────────────────────────────────────────────────────┐
│                      ВРЕМЯ ВЫПОЛНЕНИЯ                                │
└─────────────────────────────────────────────────────────────────────┘

0:00  ─┬─ git push origin deploy
       │
0:05  ─┼─ GitHub Actions обнаруживает push
       │
0:10  ─┼─ SSH подключение к серверу
       │
0:15  ─┼─ git fetch & reset
       │
0:20  ─┼─ docker-compose down (10-20 сек)
       │   └─ Приложение НЕДОСТУПНО ⚠️
       │
0:30  ─┼─ docker-compose build (2-4 мин)
       │   └─ Пересборка образов
       │
3:00  ─┼─ docker-compose up -d (20-30 сек)
       │   └─ Запуск контейнеров
       │
3:30  ─┼─ Приложение ДОСТУПНО ✅
       │
4:00  ─┴─ Деплой завершен

Общее время: 3-5 минут
Downtime: ~1-2 минуты (во время пересборки)
```

## 📈 Мониторинг процесса

```
┌─────────────────────────────────────────────────────────────────────┐
│                      ГДЕ СМОТРЕТЬ ПРОГРЕСС                          │
└─────────────────────────────────────────────────────────────────────┘

1. GitHub Actions (в браузере)
   └─ Репозиторий → Actions → Workflow "Deploy to Server"

2. На сервере (через SSH)
   ├─ docker-compose ps     → Статус контейнеров
   ├─ ./status.sh           → Полная информация
   └─ ./logs.sh             → Логи сервисов

3. Проверка работы
   ├─ http://74.119.193.196:3000  → Frontend
   └─ http://74.119.193.196:8080  → Backend API
```

## 🎯 Ключевые моменты

### ✅ Что происходит автоматически:
- Обнаружение изменений в ветке `deploy`
- SSH подключение к серверу
- Загрузка последнего кода
- Пересборка Docker образов
- Перезапуск контейнеров

### ✅ Что защищено:
- База данных (PostgreSQL) в volume `postgres-data`
- Кеш Redis в volume `redis-data`
- Файлы конфигурации (.env)

### ✅ Что можно мониторить:
- GitHub Actions (статус деплоя)
- Логи на сервере (./logs.sh)
- Статус сервисов (./status.sh)
- Доступность приложения (браузер)
